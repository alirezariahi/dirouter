# صفحهٔ MCP و ایجنت‌ها

کد: `apps/dashboard/src/pages/mcp.tsx` (توابع کمکی فرم در `src/lib/mcp.ts` و متن‌ها در
`src/i18n/mcp-page.ts`) · کارت 25.3 · مسیر `/mcp` در گروه «مسیریابی» نوار کناری.

گیت‌وی ابزارهای همهٔ سرورهای MCP ثبت‌شده را در `/mcp` (کارت 20.1) و ایجنت‌های A2A ثبت‌شده را در
`/a2a/agents/<slug>` (کارت 20.3) ارائه می‌کند؛ هر دو پشت کلید مجازی. این صفحه هر دو را از داشبورد
مدیریت می‌کند.

## بخش‌ها

| بخش                | کار                                                                                                                                                                                                         | API                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| سرورهای MCP        | سرورهای با transport ‏`streamable-http` یا `sse`: نام، slug (پیشوند ابزار)، آدرس، وضعیت، headerهای ذخیره‌شده و ارسال هویت؛ فعال/غیرفعال، ویرایش و حذف                                                       | `GET/PATCH/DELETE mcp/servers[/:id]`               |
| ایجنت‌های A2A      | سرورهای با transport ‏`a2a` و آدرسشان در گیت‌وی `/a2a/agents/<slug>`                                                                                                                                        | همان                                               |
| تست اتصال          | برای هر سرور یا ایجنت: تأخیر و ابزارهای کشف‌شده (`<slug>__<tool>`)، یا برای ایجنت مهارت‌های کارت آن                                                                                                         | `POST mcp/servers/:id/test`                        |
| ثبت / ویرایش       | نام، slug، transport، آدرس، مهلت، headerها (هر خط `Name: value`)، ارسال هویت و فعال بودن. headerهای ذخیره‌شده هرگز نمایش داده نمی‌شوند؛ در ویرایش حفظ می‌شوند مگر «جایگزینی» تیک بخورد (کادر خالی یعنی حذف) | `POST mcp/servers`، `PATCH mcp/servers/:id`        |
| دسترسی کلیدها      | انتخاب کلید و سپس «همهٔ ابزارها» (فهرست خالی) یا «فقط ابزارهای انتخاب‌شده»: `<slug>__*` هر سرور، ابزارهای کشف‌شده و الگوهای دیگر (`server__tool`، `server__*`، `*`)                                         | `PATCH keys/:id` با `mcpTools`                     |
| لاگ فراخوانی ابزار | ۱۰۰ فراخوانی آخر با فیلتر سرور، کلید و وضعیت (`success`، `error`، `denied`) همراه با زمان، ابزار، تأخیر، خطا و آرگومان‌های ماسک‌شده                                                                         | `GET mcp/calls?serverId=&apiKeyId=&status=&limit=` |

ثبت، ویرایش و تست به `mcp:write` نیاز دارد؛ بدون آن صفحه فقط‌خواندنی است. ذخیرهٔ allow-list به
`keys:write` نیاز دارد.

## تست اتصال

`POST /orgs/:orgId/mcp/servers/:id/test` (مجوز `mcp:write`) سرور ذخیره‌شده را با headerهای هنوز
رمزشده به گیت‌وی می‌فرستد (`POST /internal/mcp/probe` با توکن داخلی). گیت‌وی headerها را فقط در
حافظه رمزگشایی می‌کند، با همان کلاینت MCP ترافیک واقعی (Streamable HTTP یا HTTP+SSE) یک اتصال تازه
باز می‌کند و `tools/list` را صفحه‌به‌صفحه می‌خواند. برای ایجنت A2A کارت ایجنت
(`/.well-known/agent-card.json` زیر مسیر ایجنت و بعد در ریشهٔ origin) خوانده و مهارت‌هایش برگردانده
می‌شود. تست برای سرور غیرفعال و پیش از رسیدن snapshot سرور تازه به گیت‌وی هم کار می‌کند.

```json
{ "ok": true, "latencyMs": 87, "tools": [{ "name": "search", "description": "Search the docs" }] }
```

سرور در دسترس‌نبودن یعنی `ok: false` با متن `error` (HTTP 200)؛ گیت‌وی در دسترس‌نبودن یعنی
`503 service_unavailable`.
