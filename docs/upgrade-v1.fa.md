# ارتقا به v1.0

از هر نصب 0.x، از جمله MVP (پایان اسپرینت ۱)، به 1.0.0. این ارتقا در CI روی دادهٔ واقعی آزموده می‌شود: `apps/control-api/src/upgrade/upgrade-from-mvp.integration.test.ts` migrationهای MVP را اجرا می‌کند، داده را با schema همان نسخه می‌نویسد، ارتقا می‌دهد و بررسی می‌کند که مالک با همان رمز وارد شود، همهٔ رکوردها سالم باشند، اعتبارنامه‌های provider همچنان رمزگشایی شوند و snapshot گیت‌وی ساخته شود.

## پیش از شروع

1. **از PostgreSQL نسخهٔ پشتیبان بگیرید** (`scripts/backup/` یا snapshot سرویس‌دهنده) و یک نسخه از `.env` نگه دارید، به‌ویژه `MASTER_KEY` و `KEY_PEPPER`. این دو نباید تغییر کنند: اعتبارنامه‌های ذخیره‌شدهٔ providerها با `MASTER_KEY` رمز شده‌اند و کلیدهای مجازی با `KEY_PEPPER` hash شده‌اند.
2. امضای ایمیج‌های جدید را بررسی کنید ([SECURITY.fa.md](../SECURITY.fa.md)).

## ارتقا

با Docker Compose:

```bash
TAG=1.0.0 docker compose pull
```

```bash
TAG=1.0.0 docker compose up -d
```

سرویس `migrate` پیش از شروع control-api، migrationهای جدید را اجرا می‌کند. با Helm، `helm upgrade` را با chart جدید اجرا کنید؛ init container در control-api migration را انجام می‌دهد ([helm.fa.md](helm.fa.md)). در مدتی که control-api راه‌اندازی دوباره می‌شود، گیت‌وی‌ها از آخرین snapshot خود سرویس می‌دهند (ADR-0006).

## آنچه خودکار تغییر می‌کند

- قدیمی‌ترین سازمان **سازمان پلتفرم** (اپراتور) می‌شود که مالک صورت‌حساب، بازار مدل و کیف پول‌های سیستمی است. بقیهٔ سازمان‌ها مشتری آن می‌شوند.
- سازمان‌های موجود **پس‌پرداخت** می‌مانند (`prepaid` برابر false است) تا ترافیکشان قطع نشود. کیف پول اولین باری ساخته می‌شود که سازمان شارژ یا استفاده شود؛ هر وقت آماده بودید، سازمان را به پیش‌پرداخت ببرید.
- تأیید چهارچشمی، SAML، SCIM، افزونه‌ها و endpointهای رسانه تا تنظیم نشوند خاموش‌اند.

## تنظیمات جدید و اختیاری

همهٔ متغیرهای محیطی جدید مقدار پیش‌فرض امن دارند؛ [env-reference.fa.md](env-reference.fa.md) را ببینید. این‌ها ارزش بازبینی دارند: `PUBLIC_GATEWAY_URL` و `PUBLIC_PORTAL_URL` (لینک‌ها در پیکربندی‌های ایجنت و پورتال)، کلیدهای درگاه پرداخت و `PLUGINS_ENABLED`.

## بازگشت

نسخهٔ پشتیبان پایگاه داده را بازگردانید و ایمیج‌های قبلی را اجرا کنید. migrationها فقط رو به جلو هستند.
