# هشدارها و کانال‌های اعلان (کارت ۱۶.۲)

> کد: `apps/worker/src/alerts.ts` (ارزیابی و ارسال)، `apps/control-api/src/alerts` (CRUD و پیام آزمایشی). داشبورد: **هشدارها**.

worker هر قانون فعال را طبق برنامه ارزیابی می‌کند (`ALERT_EVALUATE_INTERVAL_MS`، پیش‌فرض ۶۰ ثانیه). وقتی مقدار یک قانون به آستانه برسد، رویدادی ساخته و به کانال آن قانون ارسال می‌شود.

## قانون‌ها

| نوع                  | مقداری که با `threshold` مقایسه می‌شود                                | واحد  |
| -------------------- | --------------------------------------------------------------------- | ----- |
| `error_rate`         | سهم درخواست‌های ناموفق در پنجره                                       | درصد  |
| `latency`            | تأخیر p95 در پنجره                                                    | ms    |
| `budget`             | هزینهٔ درخواست‌های سازمان در پنجره                                    | دلار  |
| `invalid_credential` | probeهای ناموفق احراز هویت در پنجره (نیازمند health probe، کارت ۱۲.۳) | تعداد |

- `windowMinutes` بازهٔ نگاه به عقب و `silenceMinutes` حداقل فاصلهٔ دو اعلان یک قانون است.
- **حذف تکرار**: در هر پنجرهٔ سکوت برای هر قانون فقط یک رویداد ساخته می‌شود و index یکتای `(rule, dedupKey)` آن را تضمین می‌کند؛ چند replica از worker هرگز دو بار اعلان نمی‌فرستند.
- قانونی که در پنجره‌اش ترافیکی نبوده رد می‌شود، نه اینکه فعال شود.
- قانون‌های `error_rate`، `latency` و `budget` **حتماً آستانه می‌خواهند**؛ API بدون آستانه آن‌ها را رد می‌کند و worker قانون ذخیره‌شدهٔ بدون آستانه را رد می‌کند (هرگز فعال نمی‌شود). پیش‌فرض `invalid_credential` برابر ۱ است.
- **تلاش دوبارهٔ ارسال**: پنجرهٔ سکوت فقط پس از ارسال موفق اعلان شروع می‌شود. ارسال ناموفق در نوبت‌های بعدی ارزیابی دوباره امتحان می‌شود، در مجموع حداکثر ۵ بار؛ شمار تلاش‌ها در `details.deliveryAttempts` رویداد نگه داشته می‌شود.
- `breaker_open` و `queue_length` را **API با خطای اعتبارسنجی رد می‌کند**: وضعیت breaker و طول صف جایی ذخیره نمی‌شود که worker بخواند، پس چنین قانونی هرگز فعال نمی‌شد. قانون‌هایی از این دو نوع که نسخهٔ قدیمی‌تر ذخیره کرده، نادیده گرفته می‌شوند.

## کانال‌ها

| نوع        | `config`                 | ارسال                                                                                |
| ---------- | ------------------------ | ------------------------------------------------------------------------------------ |
| `webhook`  | `url` و `secret` اختیاری | `POST` با JSON؛ با secret، بدنه در `x-dirouter-signature: sha256=<hmac>` امضا می‌شود |
| `slack`    | `webhookUrl`             | incoming webhook اسلک                                                                |
| `telegram` | `botToken`، `chatId`     | `sendMessage` در Bot API تلگرام                                                      |
| `email`    | `webhookUrl`، `to`       | از طریق relay HTTP که خودتان فراهم می‌کنید؛ **SMTP مستقیم پیاده نشده است**           |

هر کانال دکمهٔ **پیام آزمایشی** دارد (`POST /orgs/:orgId/alerts/channels/:id/test`) که همان لحظه یک اعلان آزمایشی می‌فرستد و پاسخ سرویس مقصد را نشان می‌دهد.

### رازها

پاسخ‌های کانال هرگز راز ندارند. `secret`، `botToken`، `webhookUrl` (و `url` برای همهٔ نوع‌ها جز `webhook`) به شکل `"***"` برمی‌گردند، همراه با `secretFields` (نام رازهای تنظیم‌شده) و `hasSecret`. هنگام ویرایش، رازی که فرستاده نشود یا همان `"***"` برگردد مقدار ذخیره‌شده‌اش را نگه می‌دارد؛ برای حذف، `null` یا رشتهٔ خالی بفرستید. با تغییر نوع کانال، رازهای نوع قبلی حذف می‌شوند.

### سیاست نشانی‌های خروجی

نشانی کانال را سرور صدا می‌زند، پس محدود است (پیام آزمایشی control-api و ارسال worker یک قاعده دارند):

- همیشه: نشانی مطلق `http(s)` بدون نام کاربری و گذرواژه؛ redirect دنبال نمی‌شود؛
- با `NODE_ENV=production`: فقط `https`، و همهٔ نشانی‌هایی که میزبان به آن‌ها resolve می‌شود باید عمومی باشند — بازه‌های loopback، خصوصی، link-local (از جمله نشانی metadata ابر `169.254.169.254`)، carrier-grade NAT و multicast رد می‌شوند؛
- در محیط توسعه میزبان‌های خصوصی مجازند، چون پشتهٔ توسعه به سرویس‌های آزمایشی محلی می‌فرستد.

## رویدادها

`GET /orgs/:orgId/alerts/events` رویدادها را با وضعیت و خطای ارسال فهرست می‌کند و `POST …/events/:id/ack` یکی را تأیید می‌کند. فهرست داشبورد هر ۳۰ ثانیه تازه می‌شود.

## API

`/orgs/:orgId/alerts/channels`، `/rules` و `/events` با مجوزهای `alerts:read` و `alerts:write`. ساخت، ویرایش و حذف کانال‌ها و قانون‌ها در گزارش ممیزی ثبت می‌شود (فقط نام‌ها و نام فیلدهای تغییرکرده، هرگز مقدارهای config).
