# Guardrailها

> کد: `packages/contracts/src/guardrail-engine.ts` (موتور مشترک گیت‌وی و تست زنده)، `apps/gateway/src/guardrails.ts` (stream)، `packages/contracts/src/guardrails.ts`، `apps/control-api/src/guardrails` (کارت‌های ۱۵.۱، ۱۵.۲ و ۲۳.۱). داشبورد: **Guardrailها**.

Guardrail قانونی است که گیت‌وی روی درخواست (پیش از مسیریابی) یا روی پاسخ (پیش از برگرداندن) اجرا می‌کند. سیاست‌ها در config snapshot می‌آیند و ارزیابی به هیچ فراخوان شبکه‌ای نیاز ندارد.

## سیاست

| فیلد      | مقدارها                                                                                                  |
| --------- | -------------------------------------------------------------------------------------------------------- |
| `stage`   | `request`، `response`، `both`                                                                            |
| `type`    | `regex`، `keyword`، `pii`، `secret`، `prompt_injection`، `max_input_tokens`، `json_schema`، `moderation` |
| `action`  | `block` (رد با `content_filter`)، `redact` (جایگزینی با `[REDACTED]`)، `flag` (فقط ثبت)                  |
| `config`  | وابسته به نوع؛ جدول پایین                                                                                |
| `message` | متنی که هنگام مسدودسازی به کلاینت برمی‌گردد (اختیاری)                                                    |
| دامنه     | کل سازمان، یا محدود به `projectId` / `virtualKeyId`                                                      |

| نوع                | `config`                                                       | نکته                                                                                                        |
| ------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `regex`            | `pattern` و `flags` اختیاری                                    | یک بار کامپایل و کش می‌شود؛ الگوی نامعتبر نادیده گرفته می‌شود و درخواست‌ها را خراب نمی‌کند                  |
| `keyword`          | `terms` (آرایه یا فهرست با ویرگول)، `caseSensitive`            | تطبیق عینی                                                                                                  |
| `pii`              | `type`: `email`، `credit_card`، `iban`، `national_id`، `phone` | شمارهٔ کارت باید از آزمون **Luhn** و کد ملی از رقم کنترل **mod-11** بگذرد تا عددهای معمولی علامت نخورند     |
| `secret`           | ندارد                                                          | توکن providerها، کلیدهای API و کلید خصوصی؛ بخش [رازها](#رازها)                                              |
| `prompt_injection` | `classifier` اختیاری                                           | الگوهای فارسی و انگلیسیِ دور زدن دستورها، به‌علاوهٔ مدل طبقه‌بند اختیاری؛ بخش [تزریق پرامپت](#تزریق-پرامپت) |
| `max_input_tokens` | `maxTokens`                                                    | مرحلهٔ درخواست؛ با اندازهٔ تخمینی ورودی مقایسه می‌شود                                                       |
| `json_schema`      | `schema`                                                       | فقط مرحلهٔ پاسخ؛ پاسخ باید JSON باشد و با اسکیما بخواند؛ بخش [JSON Schema](#json-schema)                    |
| `moderation`       | `model`، `mode`، `thresholds`، `timeoutMs`، `failMode`         | یک مدل تعدیل محتوا متن را از طریق خود گیت‌وی می‌سنجد؛ بخش [تعدیل محتوا](#تعدیل-محتوا)                       |

سیاست‌ها به ترتیب اجرا می‌شوند و اولین سیاست مسدودکننده ارزیابی را متوقف می‌کند. hitها (سیاست، نوع، اقدام، تعداد تطابق) برای درخواست، پاسخ، stream و پاسخ کش‌شده در لاگ گیت‌وی (`guardrail hits`) ثبت می‌شوند؛ متن تطبیق‌یافته ثبت نمی‌شود.

> **پیش از v1.1 (کارت ۲۳.۱)** گیت‌وی سیاست‌های `secret` و `json_schema` را بی‌صدا رد می‌کرد: ساخته می‌شدند و از تست زنده هم می‌گذشتند، ولی ترافیک واقعی هرگز بررسی نمی‌شد. از v1.1 اجرا می‌شوند. پیش از ارتقا، سیاست‌های `secret` و `json_schema` موجود با `action: block` را مرور کنید: درخواست یا پاسخی که با آن‌ها تطبیق کند حالا رد می‌شود.

## رازها

نوع `secret` دنبال اعتبارنامه‌هایی می‌گردد که پیشوند ثابت و بدنه‌ای به اندازهٔ کلید دارند، تا متن عادی تطبیق نخورد:

| تشخیص‌دهنده             | شکل نمونه                                         |
| ----------------------- | ------------------------------------------------- |
| کلید OpenAI و Anthropic | `sk-…`، `sk-proj-…`، `sk-ant-…` (دست‌کم ۲۰ نویسه) |
| کلید مجازی DiRouter     | `dr-xxxxxxxx-…` (۴۰ نویسه)                        |
| شناسهٔ کلید دسترسی AWS  | `AKIA…`، `ASIA…`                                  |
| توکن GitHub             | `ghp_…`، `gho_…`، `ghs_…`، `github_pat_…`         |
| توکن Slack              | `xoxb-…`، `xoxp-…`                                |
| کلید API گوگل           | `AIza…`                                           |
| کلید Stripe             | `sk_live_…`، `rk_test_…`                          |
| JWT                     | `eyJ….eyJ….…`                                     |
| کلید خصوصی PEM          | از `-----BEGIN … PRIVATE KEY-----` تا خط END      |

کلید PEM یک بلوک حساب می‌شود: با `redact` کل بلوک یک `[REDACTED]` می‌شود. کلیدی که خط END ندارد (پاسخی که با `max_tokens` بریده شده) از خط BEGIN تا انتها حذف می‌شود. تست زنده از هر تطابق فقط هشت نویسهٔ اول را نشان می‌دهد.

## JSON Schema

سیاست `json_schema` پاسخ مدل را می‌سنجد، نه prompt را؛ در مرحلهٔ درخواست کاری نمی‌کند. پاسخ باید JSON باشد (یک حصار Markdown دور آن، مثل ` ```json `، مجاز است) و با `config.schema` بخواند.

کلیدواژه‌های پشتیبانی‌شده: `type` (یکی یا فهرست)، `enum`، `const`، `properties`، `required`، `additionalProperties`، `items`، `minItems`، `maxItems`، `minLength`، `maxLength` (بر حسب code point)، `pattern`، `minimum`، `maximum`، `exclusiveMinimum`، `exclusiveMaximum`، `anyOf`، `oneOf`، `allOf`. annotationها (`title`، `description`، `$schema`، `format`، `default`، `examples` و …) پذیرفته و نادیده گرفته می‌شوند.

خود اسکیما هنگام ذخیرهٔ سیاست بررسی می‌شود: هر کلیدواژهٔ دیگر (مثل `$ref` یا `if`)، نوع ناشناخته یا `pattern`ی که ممکن است backtracking فاجعه‌بار داشته باشد با `400` رد می‌شود. پس هرگز اسکیمایی ذخیره نمی‌شود که گیت‌وی فقط نیمی از آن را اجرا کند.

`block` پاسخ ناسازگار را رد می‌کند؛ `flag` آن را عبور می‌دهد و hit را با تعداد ایرادها ثبت می‌کند؛ `redact` برای یک سند معنایی ندارد و مثل `flag` رفتار می‌کند. هنگام بررسی پاسخ، provider پاسخ داده و هزینه‌اش حساب شده است.

## تعدیل محتوا

سیاست `moderation` (کارت ۲۳.۲، از v1.1) متن را به یک مدل تعدیل محتوا می‌فرستد. این فراخوانی **از طریق خود گیت‌وی** و با کلید خود فراخواننده انجام می‌شود: مثل هر درخواست دیگری مسیریابی (با fallback)، محدودیت نرخ، کسر از کیف پول و ثبت در مصرف دارد، با شناسهٔ درخواست جدا (`<request id>-guard-request-0`). جای دومی از سقف هم‌زمانی کلید نمی‌گیرد. کلید باید اجازهٔ استفاده از مدل تعدیل را داشته باشد.

| `config`     | معنا                                                                                                                                                                                                                              | پیش‌فرض       |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| `model`      | مدل یا alias مدل تعدیل (الزامی)                                                                                                                                                                                                   |               |
| `mode`       | `moderations`: endpoint سازگار با `/moderations` اوپن‌ای‌آی (`omni-moderation-latest` یا هر سرور با همین API)؛ `llama_guard`: مدل چتی که `safe` یا `unsafe` و کد دسته‌ها را برمی‌گرداند (Llama Guard روی vLLM، Groq، Together و…) | `moderations` |
| `thresholds` | دسته ← حداقل امتیاز، مثلاً `{"violence": 0.7, "hate": 0.5}`. فقط دسته‌های فهرست‌شده حساب می‌شوند. بدون آن، `flagged` خود provider تصمیم می‌گیرد. در `llama_guard` کدهایی را که حساب می‌شوند فهرست می‌کند (`{"S1": 1}`)            | ندارد         |
| `timeoutMs`  | مدت انتظار گیت‌وی برای حکم (۵۰ تا ۳۰۰۰۰)                                                                                                                                                                                          | `2000`        |
| `failMode`   | `open`: اگر مدل دیر کرد یا خطا داد درخواست عبور می‌کند؛ `closed`: رد می‌شود                                                                                                                                                       | `open`        |

`block` با `content_filter` رد می‌کند؛ `flag` برخورد را با دسته‌ها ثبت می‌کند؛ `redact` مثل `flag` رفتار می‌کند. با `stage: both` درخواست پیش از مسیریابی و پاسخ پس از آن سنجیده می‌شود. در stream با `block` کل پاسخ تا کامل شدن نگه داشته و بعد سنجیده می‌شود؛ با `flag` متن جریان دارد و حکم در پایان ثبت می‌شود.

کلاینت‌ها هم می‌توانند همین مدل‌ها را مستقیم با `POST /v1/moderations` (قالب OpenAI، ببینید [endpoint نظارت محتوا](../gateway/moderations.fa.md)) صدا بزنند.

هر فراخوانی در `dirouter_gateway_guardrail_calls_total{type, outcome}` (`pass`، `flagged`، `timeout`، `error`) شمرده می‌شود و timeout یا خطا در لاگ سطح `warn` هم ثبت می‌شود.

تست زندهٔ پنل مدلی را صدا نمی‌زند: برای این سیاست‌ها همین را می‌گوید (`needsModelCall`) و حکم مدل فقط روی ترافیک واقعی اعمال می‌شود.

## تزریق پرامپت

الگوهای داخلی (کارت ۲۳.۳) فارسی و انگلیسی‌اند: دستور به نادیده گرفتن یا فراموش کردن دستورهای قبلی، درخواست فاش کردن پرامپت سیستمی، تغییر نقش به حالت بی‌محدودیت (DAN، حالت توسعه‌دهنده، جیلبریک)، برچسب نقش جعلی (`</system>`، `<|im_start|>`)، متن خطاب به هوش مصنوعی درون سند یا خروجی ابزار، و درخواست فرستادن کلید یا مکالمه به یک نشانی. نشانه‌های قوی امتیاز ۲ و ضعیف ۱ دارند و سیاست از ۲ فعال می‌شود، پس یک نشانهٔ ضعیف به‌تنهایی مسدود نمی‌کند. خروجی ابزارها (`tool_result`) هم مثل پیام کاربر ورودی نامطمئن حساب و اسکن می‌شود.

فایل `packages/contracts/src/__fixtures__/guardrails/prompt-injection.json` پنجاه نمونهٔ حمله و پنجاه نمونهٔ سالم دارد، نیمی فارسی و نیمی انگلیسی، با نمونه‌های مرزی مثل «داده‌های پرت را نادیده بگیر» یا روشن کردن حالت توسعه‌دهندهٔ اندروید. تست `guardrail-engine.injection.test.ts` نرخ‌ها را چاپ می‌کند و اگر تشخیص در هر زبان زیر ۹۰٪ یا خطای مثبت بالای ۴٪ برود CI شکست می‌خورد. وضعیت فعلی: انگلیسی ۱۰۰٪ تشخیص و ۰٪ خطای مثبت، فارسی ۱۰۰٪ و ۰٪. این مجموعه هم‌زمان با الگوها نوشته شده، پس این اعداد فقط نشان می‌دهند الگوها همین مجموعه را پوشش می‌دهند، نه کارکردشان روی حمله‌های ندیده؛ طبقه‌بند برای چیزهایی است که الگو نمی‌گیرد.

طبقه‌بند اختیاری یک مدل چت کوچک را هم صدا می‌زند:

```json
{
  "classifier": {
    "model": "my-small-model",
    "threshold": 0.5,
    "timeoutMs": 2000,
    "failMode": "open"
  }
}
```

از مدل خواسته می‌شود `{"injection": true|false, "score": 0..1}` برگرداند؛ امتیاز برابر یا بالاتر از `threshold` مثل یک الگوی قوی حساب می‌شود. فراخوانی مثل تعدیل محتوا از گیت‌وی می‌گذرد و همان قواعد timeout و `failMode` را دارد (پیش‌فرض `open`: اگر طبقه‌بند در دسترس نباشد الگوها همچنان اجرا می‌شوند).

## نوع ناشناختهٔ سیاست

سیاستی که این گیت‌وی نوعش را اجرا نمی‌کند (مثلاً نوعی که control plane جدیدتر در میانهٔ ارتقای تدریجی اضافه کرده) کنار گذاشته می‌شود، ولی نه بی‌صدا: گیت‌وی پیام `guardrail policy of an unknown type was not enforced` را در سطح `warn` با شناسه و نوع سیاست ثبت می‌کند و آن را در `dirouter_gateway_guardrail_unknown_total{type}` می‌شمارد. snapshot معتبر می‌ماند و فقط همان سیاست اجرا نمی‌شود.

## Stream

سیاست‌های پاسخ روی stream هم اعمال می‌شوند (`StreamGuardrailBuffer`):

- فقط **کلمه‌های کامل** ارزیابی می‌شوند. کلمه‌ای که هنوز در حال رسیدن است نگه داشته می‌شود؛ چون تطبیق زودهنگام، `user@example.co` را حذف و حرف `m` تکهٔ بعدی را نشت می‌داد.
- ۲۵۶ نویسهٔ آخرِ متن ارزیابی‌شده هم نگه داشته می‌شود تا الگوهای چندکلمه‌ای که در تکه‌های بعد ادامه دارند تطبیق پیدا کنند؛ متن فقط در مرز فاصله آزاد می‌شود. پس تکه‌ای که به کلاینت می‌رسد هرگز وسط یک کلمه تمام نمی‌شود.
- تطبیق مسدودکننده stream را با رویداد خطای `content_filter` می‌بندد و چیزی بعد از آن ارسال نمی‌شود. در پایان stream، دنبالهٔ نگه‌داشته‌شده یک بار دیگر ارزیابی می‌شود.
- رشتهٔ بدون فاصلهٔ بلندتر از چهار پنجره (۱۰۲۴ نویسه) به هر حال ارزیابی و آزاد می‌شود تا حافظه و تأخیر سقف داشته باشد.
- با سیاست `secret`، کلید خصوصی PEM از خط BEGIN تا رسیدن خط END (تا ۱۶ کیلوبایت) نگه داشته می‌شود تا هیچ خطی از کلید پیش از تطبیق کل بلوک نشت نکند.
- سیاستی با `block` که کل پاسخ را می‌سنجد (`json_schema`، `moderation`، طبقه‌بند تزریق پرامپت) **همهٔ رویدادهای stream** را، نه فقط متن، تا پایان پاسخ upstream نگه می‌دارد. کل پاسخ یک بار سنجیده می‌شود؛ پاسخ ردشده stream را با رویداد خطا می‌بندد و هیچ بخشی از آن ارسال نمی‌شود. پاسخ پذیرفته‌شده به همان ترتیب اصلی بازپخش می‌شود و هر بلوک متن همچنان از سیاست‌های دیگر (مثل حذف متن حساس) می‌گذرد. پس متنِ بعد از فراخوانی ابزار یا در بلوک بعدی Anthropic هم سنجیده می‌شود. headerها و heartbeat بلافاصله فرستاده می‌شوند تا کلاینت در انتظار timeout نشود. پاسخ بزرگ‌تر از ۱ مگابایت قابل سنجش نیست و مسدود می‌شود. با `flag` متن عادی جریان دارد و حکم یک بار، روی کل پاسخ، در پایان stream ثبت می‌شود.

هزینهٔ این کار تأخیر است: وقتی سیاست پاسخ فعال است، متن stream حدود ۲۵۶ نویسه دیرتر به کلاینت می‌رسد. streamهای بدون سیاست پاسخ اصلاً بافر نمی‌شوند.

## سربار

`guardrails.test.ts` یک سیاست regex را روی prompt چهار کیلوبایتی می‌سنجد: حدود **۰٫۰۰۳ میلی‌ثانیه** برای هر بررسی روی ماشین توسعه، در برابر بودجهٔ ۱ میلی‌ثانیه.

## تست سیاست پیش از ذخیره

`POST /orgs/:orgId/guardrails/test` با `{type, action, config, text}` می‌گوید متن مسدود می‌شود یا نه (`blocked`)، اصلاً سیاست تطبیق خورد یا نه (`hit`، برای `flag` هم)، و تطابق‌ها و متن redactشده را برمی‌گرداند، بدون اینکه چیزی ذخیره شود. در `json_schema` متن به‌عنوان پاسخ مدل سنجیده می‌شود و پاسخ `valid` و `schemaErrors` هم دارد. فرم داشبورد یک کادر **تست زنده** دارد که از همین استفاده می‌کند.

تست زنده خود موتور گیت‌وی را اجرا می‌کند (`packages/contracts/src/guardrail-engine.ts`)، پس نتیجه‌اش همان نتیجهٔ ترافیک واقعی است. جدول مشترک نمونه‌ها، `packages/contracts/src/__fixtures__/guardrails/conformance.json`، هم در تست‌های گیت‌وی (درخواست، پاسخ و stream) و هم در تست‌های control plane اجرا می‌شود؛ تغییری که این دو را ناهم‌خوان کند در CI شکست می‌خورد.

## API مدیریت

`GET|POST /orgs/:orgId/guardrails` و `PATCH|DELETE /orgs/:orgId/guardrails/:id` (مجوزهای `guardrails:read` و `guardrails:write`). تغییرها به‌صورت نسخهٔ جدید config به گیت‌وی‌ها می‌رسند و در لاگ ممیزی ثبت می‌شوند.
