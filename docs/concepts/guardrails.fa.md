# Guardrailها

> کد: `apps/gateway/src/guardrails.ts`، `packages/contracts/src/guardrails.ts`، `apps/control-api/src/guardrails` (کارت‌های ۱۵.۱ و ۱۵.۲). داشبورد: **Guardrailها**.

Guardrail قانونی است که گیت‌وی روی درخواست (پیش از مسیریابی) یا روی پاسخ (پیش از برگرداندن) اجرا می‌کند. سیاست‌ها در config snapshot می‌آیند و ارزیابی به هیچ فراخوان شبکه‌ای نیاز ندارد.

## سیاست

| فیلد      | مقدارها                                                                                    |
| --------- | ------------------------------------------------------------------------------------------ |
| `stage`   | `request`، `response`، `both`                                                              |
| `type`    | `regex`، `keyword`، `pii`، `secret`، `prompt_injection`، `max_input_tokens`، `json_schema` |
| `action`  | `block` (رد با `content_filter`)، `redact` (جایگزینی با `[REDACTED]`)، `flag` (فقط ثبت)    |
| `config`  | وابسته به نوع؛ جدول پایین                                                                  |
| `message` | متنی که هنگام مسدودسازی به کلاینت برمی‌گردد (اختیاری)                                      |
| دامنه     | کل سازمان، یا محدود به `projectId` / `virtualKeyId`                                        |

| نوع                | `config`                                                       | نکته                                                                                                    |
| ------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `regex`            | `pattern` و `flags` اختیاری                                    | یک بار کامپایل و کش می‌شود؛ الگوی نامعتبر نادیده گرفته می‌شود و درخواست‌ها را خراب نمی‌کند              |
| `keyword`          | `terms` (آرایه یا فهرست با ویرگول)، `caseSensitive`            | تطبیق عینی                                                                                              |
| `pii`              | `type`: `email`، `credit_card`، `iban`، `national_id`، `phone` | شمارهٔ کارت باید از آزمون **Luhn** و کد ملی از رقم کنترل **mod-11** بگذرد تا عددهای معمولی علامت نخورند |
| `secret`           | ندارد                                                          | توکن providerها، کلیدهای API و کلید خصوصی                                                               |
| `prompt_injection` | ندارد                                                          | امتیاز heuristic روی الگوهای «دستور قبلی را نادیده بگیر»؛ از امتیاز ۲ به بالا فعال می‌شود               |
| `max_input_tokens` | `maxTokens`                                                    | مرحلهٔ درخواست؛ با اندازهٔ تخمینی ورودی مقایسه می‌شود                                                   |
| `json_schema`      | `schema`                                                       | مرحلهٔ پاسخ؛ متن باید parse شود و با زیرمجموعهٔ کوچکی از JSON Schema سازگار باشد                        |

سیاست‌ها به ترتیب اجرا می‌شوند و اولین سیاست مسدودکننده ارزیابی را متوقف می‌کند. hitها (سیاست، نوع، اقدام، تعداد تطابق) همراه درخواست ثبت می‌شوند؛ متن تطبیق‌یافته ثبت نمی‌شود.

## Stream

سیاست‌های پاسخ روی stream هم اعمال می‌شوند (`StreamGuardrailBuffer`):

- فقط **کلمه‌های کامل** ارزیابی می‌شوند. کلمه‌ای که هنوز در حال رسیدن است نگه داشته می‌شود؛ چون تطبیق زودهنگام، `user@example.co` را حذف و حرف `m` تکهٔ بعدی را نشت می‌داد.
- ۲۵۶ نویسهٔ آخرِ متن ارزیابی‌شده هم نگه داشته می‌شود تا الگوهای چندکلمه‌ای که در تکه‌های بعد ادامه دارند تطبیق پیدا کنند؛ متن فقط در مرز فاصله آزاد می‌شود. پس تکه‌ای که به کلاینت می‌رسد هرگز وسط یک کلمه تمام نمی‌شود.
- تطبیق مسدودکننده stream را با رویداد خطای `content_filter` می‌بندد و چیزی بعد از آن ارسال نمی‌شود. در پایان stream، دنبالهٔ نگه‌داشته‌شده یک بار دیگر ارزیابی می‌شود.
- رشتهٔ بدون فاصلهٔ بلندتر از چهار پنجره (۱۰۲۴ نویسه) به هر حال ارزیابی و آزاد می‌شود تا حافظه و تأخیر سقف داشته باشد.

هزینهٔ این کار تأخیر است: وقتی سیاست پاسخ فعال است، متن stream حدود ۲۵۶ نویسه دیرتر به کلاینت می‌رسد. streamهای بدون سیاست پاسخ اصلاً بافر نمی‌شوند.

## سربار

`guardrails.test.ts` یک سیاست regex را روی prompt چهار کیلوبایتی می‌سنجد: حدود **۰٫۰۰۳ میلی‌ثانیه** برای هر بررسی روی ماشین توسعه، در برابر بودجهٔ ۱ میلی‌ثانیه.

## تست سیاست پیش از ذخیره

`POST /orgs/:orgId/guardrails/test` با `{type, action, config, text}` می‌گوید متن مسدود می‌شود یا نه و تطابق‌ها و متن redactشده را برمی‌گرداند، بدون اینکه چیزی ذخیره شود. فرم داشبورد یک کادر **تست زنده** دارد که از همین استفاده می‌کند؛ پیش‌نمایش و گیت‌وی قاعدهٔ اعتبارسنجی یکسانی دارند.

## API مدیریت

`GET|POST /orgs/:orgId/guardrails` و `PATCH|DELETE /orgs/:orgId/guardrails/:id` (مجوزهای `guardrails:read` و `guardrails:write`). تغییرها به‌صورت نسخهٔ جدید config به گیت‌وی‌ها می‌رسند و در لاگ ممیزی ثبت می‌شوند.
